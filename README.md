# AI 社群圖文生成器（GitHub → Vercel 版）

網站會標示各功能是否使用 AI：成效預估依歷史資料計算，預設圖片與三種開場由程式產生，均不使用 AI。設定伺服器端 API Key 與使用密碼後，可選「整張海報由 AI 重製」或「AI 背景＋原檔合成」。前者會將目前圖片預覽壓縮後傳給 Gemini 作為參考，讓 AI 重做素材、文字與版型；後者維持原廠素材及程式文字。兩種 AI 模式的文案開場都以約 25–30 字為目標，活動時間與參加方式由固定段落呈現。

這是 [gtw-bu1/FBcampaign](https://github.com/gtw-bu1/FBcampaign) 的 React／Vite 網站。Vercel 執行 `npm run build`，發布 `dist`。沒有 API Key 也能按「依活動名稱產生 3 種開場」：網站會依活動名稱與獎勵提供三種不同切入角度的開場，重新產生會避開近期用過的版本，並參考歷史 FB 文案的活動標題、親近邀請、貼心提醒與口語句尾。活動事實只取自本次輸入。這是瀏覽器內的規則式草稿，沒有呼叫 AI。`api/generate.js` 已支援 Gemini 或 OpenAI，但必須先設定伺服器端金鑰才能使用。

## 發布流程

1. 在 Vercel 選 **Add New → Project → Import Git Repository**，選 [gtw-bu1/FBcampaign](https://github.com/gtw-bu1/FBcampaign)。
2. Framework 選 Vite；建置指令 `npm run build`；輸出目錄 `dist`；Root Directory 留空或選專案根目錄。
3. 按 Deploy。之後每次推送到 `main`，Vercel 會重新建置。這個 GitHub 專案目前是公開的；網站的存取權仍由 Vercel 專案設定決定。

## 啟用 AI

1. 在 [Google AI Studio](https://aistudio.google.com/api-keys) 建立 Gemini API Key，確認帳戶可使用文字模型 `gemini-3.8-flash` 和圖片模型 `gemini-nano-banana-2.1`，並留意用量和費用。
2. 到 **Vercel 專案 → Settings → Environment Variables**，新增 `GEMINI_API_KEY`（你的 API Key）與 `FB_CAMPAIGN_ACCESS_CODE`（自行產生、至少 24 字元的高強度使用密碼）。兩者都設定給 Production；要測試預覽版時，也設定給 Preview。API Key 不可貼到 GitHub、網站欄位或聊天訊息中。若同時設定 `GEMINI_API_KEY` 與 `OPENAI_API_KEY`，網站優先使用 Gemini。
3. 在 Vercel 重新部署最新的 `main`，讓新環境變數生效。進入網站後，在「使用密碼」輸入 `FB_CAMPAIGN_ACCESS_CODE`，選擇產圖方式後按 AI 生成按鈕。密碼只保留在當前頁面的記憶體，不儲存到瀏覽器永久空間。

API Key 只在 Vercel Function 的伺服器端使用。公開網站的生成入口要求使用密碼；未設定金鑰與使用密碼時，API 回報未啟用，不會暗中使用模擬內容。保留原有 OpenAI 支援：若沒有 Gemini Key，可設定 `OPENAI_API_KEY`（文字 `gpt-4.1-mini`、圖片 `gpt-image-2.5-flare`）。

## 本機驗證

需要 Node.js 22 以上。執行 `npm ci`、`npm test`、`npm run build`。本機預覽可執行 `npm run dev`；若要在本機呼叫 `api/generate.js`，需用 `vercel dev` 並在本機環境中設定上述變數。不要提交 `.env` 或 `.env.local`。

## 功能與限制

### 成效預估與歷史資料

- 右側「圖片預覽／社群文案／成效預估」分頁讓左側圖片與文案設定保持連續可見；在「成效預估」分頁，工具會依活動文字提出可修改的文字類型初判。參加條件用「留言即可／需附上圖片／需附上影片／需達上線時間門檻／需進行投稿」對照；獎勵用「體驗型天數道具／免費且不稀有／免費但稀有／有明確金額價值」對照。金額型獎勵須填單份主要獎勵的台幣估值。開始與結束日期可自行調整，活動天數自動計算且包含首尾兩天。檔期與獎勵發放方式仍由使用者確認。
- 可逐筆保存歷史活動，或下載新版 CSV 範本後以 Excel 填寫再匯入。請填活動名稱、開始日期、結束日期、參加條件類型、獎勵類型、檔期（淡季／平季／旺季）、最終參與人數與獎勵發放方式（抽獎／符合條件即送／混合）；金額型獎勵須填「獎勵金額（NT$）」。日期格式為 `YYYY-MM-DD`；參與人數應使用一致的「不重複參加者」口徑。活動條件、獎勵內容、曝光人數為選填。
- 舊版數字欄位 CSV 仍可匯入；舊分數無法可靠推斷現在的文字類型，難易度與獎勵都會標為「未分類」，需在網站補選後才納入估算。至少 5 檔已分類活動、其中至少 3 檔與本次活動的發放方式相同，才顯示初步人數範圍和最相近案例。單一發放方式至少 8 檔才顯示其他因素與參與人數的方向性關聯。關聯不代表因果；曝光量、宣傳投入、遊戲人口變動等因素尚未校正。範圍只供規劃，不是保證或統計信賴區間。
- 歷史資料只存在目前瀏覽器，換裝置不會同步；請用「匯出備份」保存 CSV。資料不會傳送到 AI 服務。

- 填活動名稱、時間、獎勵與條件；上傳最多 8 張 PNG／JPG／WebP 原廠素材，標註角色、道具、獎勵 ICON 或 Logo。
- 選「AI 背景＋原檔合成」時，原廠素材保留原始檔案，只在輸出 Canvas 以完整等比例方式縮放；不傳給 AI、不重繪、不套濾鏡。選「整張海報由 AI 重製」時，瀏覽器會先把上傳素材和圖片文字合成一張 JPEG 參考圖，再傳給 Gemini 重新設計；原始檔不直接上傳，但其內容會出現在參考圖中，AI 成品可能改動角色、Logo、獎勵道具或中文字。
- 「圖片創作風格」可設定主標、副標、素材名稱顯示、選填 CTA、主題色、八種可複選氛圍與圖片想法。沒有上傳素材時會繪製可直接下載的萬用裝飾圖；它是程式生成的圖形，不是 AI 圖片。離線版的圖片想法只辨識星空、花朵、霓虹、科技等關鍵字。
- 雙欄畫面下，右側圖片／文案預覽固定在視窗內；點入左側圖片創作欄位時自動切到圖片預覽。窄版單欄畫面仍依上下順序排列。
- 「文案創作風格」集中設定語氣、Hashtags、歷史 FB 文字及參考圖；已保存的 FB 文字會在同一瀏覽器保留。圖片文字直接在圖片區修改，不另設重複的微調區塊。
- 編輯與複製社群文案，下載 1200×1200 或 1200×628 PNG。圖片上的標題與 CTA 可另外編輯。
- 每篇固定附上 `#CSO絕對武力`；八個預設活動標籤可勾選，也可加自訂 Hashtags。重複標籤只輸出一次，勾選狀態會和 FB 文案一起保存在同一個瀏覽器。
- 離線文案草稿會依活動名稱選擇主題意象，並參考最多 20 篇歷史文案的表面語氣特徵；近期用過的開場記錄在同一個瀏覽器，重新產生時會優先避開。不複製舊活動事實。這是有限組合的離線草稿，不等於無限制的 AI 創作。AI 文字功能只產生約 25–30 字的宣傳開頭，不重複活動時間與參加方式；活動時間、獎勵與條件由程式原樣放入文案。最多三篇歷史文案可送至伺服器參考語氣；FB 參考圖不傳給 AI。
- 可匯入／匯出 JSON 風格規則，也可加入歷史 FB 文案與參考圖。歷史文字與尚未保存成案例的貼文會自動存在同一個瀏覽器、同一個網站網域的本機儲存區；再次開啟不必重貼。換裝置、使用另一個部署網址或清除瀏覽器資料時不會同步，請匯出 JSON 備份。參考圖與原廠素材重新整理後會清除。
- Gemini 圖片選用 `gemini-nano-banana-2.1`、文字選用 `gemini-3.8-flash`；若使用 OpenAI，仍只支援背景＋原檔合成（背景 `gpt-image-2.5-flare`、文字 `gpt-4.1-mini`）。完整 AI 海報由前端按所選尺寸輸出 PNG；若改動圖片設定，須重新生成才可下載。完整 AI 海報的中文字、活動數字、角色與 Logo 無法保證完全正確，發布前務必人工校對。

本版本沒有登入、雲端儲存或 FB 自動發文。若將來要讓多位同事保存活動與素材，需要額外加入權限和資料庫。
