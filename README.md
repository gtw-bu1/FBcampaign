# AI 社群圖文生成器（GitHub → Vercel 版）

## 版本更新歷程

每次正式部署都要在 `src/changelog.mjs` 最上方新增一筆版本、日期與實際變更項目；網站右上角「版本更新」會直接顯示這份紀錄。本次 v1.3.0 加入固定貼文標題、分行 emoji 開場、AI 潤飾參加方式、活動相關結尾，以及兩種尺寸同步微調。v1.2.0 加入雙尺寸產圖、較長開場及 30 天登入記憶。較早版本未建立逐次紀錄，因此不補寫成虛構的部署項目。

網站會標示各功能是否使用 AI：成效預估依歷史資料計算，不使用 AI。圖文按鈕使用 Gemini 一次生成兩種尺寸的完整海報與一份文案。兩張圖各自按照 1200×1200 與 1200×628 的構圖產生，切換尺寸不會重新拉伸舊圖。海報會以各尺寸的參考排版及至多三張主要素材的壓縮圖為參考，讓 Gemini 自行判斷主角色／獎勵的視覺比例；文案固定以「【活動名稱】主要獎勵送給你！」開頭，接續帶 emoji 並分行的 2–3 句開場、活動資訊、潤飾後的參加方式及活動相關的邀請結尾。「用 AI 再換 3 種開場」只更新開場、保留兩張圖片與貼文其餘段落；圖片微調會以相同指示重製兩種尺寸，兩張都成功才取代原圖，也可一起復原。

這是 [gtw-bu1/FBcampaign](https://github.com/gtw-bu1/FBcampaign) 的 React／Vite 網站。Vercel 執行 `npm run build`，發布 `dist`。圖文創作介面使用 Gemini；沒有 Gemini Key 時仍可查看排版預覽與使用歷史資料成效預估，但不能產生 AI 海報與文案。

## 發布流程

1. 在 Vercel 選 **Add New → Project → Import Git Repository**，選 [gtw-bu1/FBcampaign](https://github.com/gtw-bu1/FBcampaign)。
2. Framework 選 Vite；建置指令 `npm run build`；輸出目錄 `dist`；Root Directory 留空或選專案根目錄。
3. 按 Deploy。之後每次推送到 `main`，Vercel 會重新建置。這個 GitHub 專案目前是公開的；網站的存取權仍由 Vercel 專案設定決定。

## 啟用 AI

1. 在 [Google AI Studio](https://aistudio.google.com/api-keys) 建立 Gemini API Key，確認帳戶可使用文字模型 `gemini-3.8-flash` 和圖片模型 `gemini-nano-banana-2.1`，並留意用量和費用。
2. 到 **Vercel 專案 → Settings → Environment Variables**，新增 `GEMINI_API_KEY`（你的 API Key）與 `FB_CAMPAIGN_ACCESS_CODE`（自行產生、至少 24 字元的高強度使用密碼）。兩者都設定給 Production；要測試預覽版時，也設定給 Preview。API Key 不可貼到 GitHub、網站欄位或聊天訊息中。
3. 在 Vercel 重新部署最新的 `main`，讓新環境變數生效。進入網站後，在「使用密碼」輸入 `FB_CAMPAIGN_ACCESS_CODE`，按「AI 一次生成兩種尺寸海報與文案」。成功驗證後，伺服器會設定 30 天有效的安全登入 Cookie；同一台瀏覽器下次開啟網站不必重輸。可按「忘記這台裝置」清除登入。Gemini API Key 始終只存放在 Vercel，不在網站輸入。

API Key 只在 Vercel Function 的伺服器端使用。公開網站的生成入口要求使用密碼；未設定 Gemini 金鑰與使用密碼時，AI 圖文功能不可用。舊版 OpenAI 背景合成路徑仍留在 API 供相容性使用，新的圖文介面只提供 Gemini 完整海報。

## 本機驗證

需要 Node.js 22 以上。執行 `npm ci`、`npm test`、`npm run build`。本機預覽可執行 `npm run dev`；若要在本機呼叫 `api/generate.js`，需用 `vercel dev` 並在本機環境中設定上述變數。不要提交 `.env` 或 `.env.local`。

## 功能與限制

### 成效預估與歷史資料

- 右側「圖片預覽／社群文案／成效預估」分頁讓左側圖片與文案設定保持連續可見；在「成效預估」分頁，工具會依活動文字提出可修改的文字類型初判。參加條件用「留言即可／需附上圖片／需附上影片／需達上線時間門檻／需進行投稿」對照；獎勵用「體驗型天數道具／免費且不稀有／免費但稀有／有明確金額價值」對照。金額型獎勵須填單份主要獎勵的台幣估值。開始與結束日期可自行調整，活動天數自動計算且包含首尾兩天。檔期與獎勵發放方式仍由使用者確認。
- 可逐筆保存歷史活動，或下載新版 CSV 範本後以 Excel 填寫再匯入。請填活動名稱、開始日期、結束日期、參加條件類型、獎勵類型、檔期（淡季／平季／旺季）、最終參與人數與獎勵發放方式（抽獎／符合條件即送／混合）；金額型獎勵須填「獎勵金額（NT$）」。日期格式為 `YYYY-MM-DD`；參與人數應使用一致的「不重複參加者」口徑。活動條件、獎勵內容、曝光人數為選填。
- 舊版數字欄位 CSV 仍可匯入；舊分數無法可靠推斷現在的文字類型，難易度與獎勵都會標為「未分類」，需在網站補選後才納入估算。至少 5 檔已分類活動、其中至少 3 檔與本次活動的發放方式相同，才顯示初步人數範圍和最相近案例。單一發放方式至少 8 檔才顯示其他因素與參與人數的方向性關聯。關聯不代表因果；曝光量、宣傳投入、遊戲人口變動等因素尚未校正。範圍只供規劃，不是保證或統計信賴區間。
- 歷史資料只存在目前瀏覽器，換裝置不會同步；請用「匯出備份」保存 CSV。資料不會傳送到 AI 服務。

- 填活動名稱、時間、獎勵與條件；上傳最多 8 張 PNG／JPG／WebP 原廠素材，標註角色、道具、獎勵 ICON 或 Logo。
- 上傳素材與圖片文字會先合成 JPEG 參考海報；至多三張素材會另外縮成細節參考圖，讓 Gemini 看清主要角色與獎勵。原始檔不直接上傳，但其內容會出現在參考圖中；AI 成品可能改動角色、Logo、獎勵道具或中文字。
- 「圖片創作風格」可設定主標、副標、素材名稱顯示、選填 CTA、主題色、八種可複選氛圍與圖片想法。沒有上傳素材時，Gemini 會依活動資訊與圖片想法設計通用主視覺。圖片預覽在 AI 生成前只是程式繪製的參考排版。
- 雙欄畫面下，右側圖片／文案預覽固定在視窗內；點入左側圖片創作欄位時自動切到圖片預覽。窄版單欄畫面仍依上下順序排列。
- 「文案創作風格」集中設定語氣、Hashtags、歷史 FB 文字及參考圖；已保存的 FB 文字會在同一瀏覽器保留。圖片文字直接在圖片區修改，不另設重複的微調區塊。
- 編輯與複製社群文案，一次生成後可切換並下載 1200×1200 或 1200×628 PNG。圖片上的標題與 CTA 可在生成前設定。
- 每篇固定附上 `#CSO絕對武力`；八個預設活動標籤可勾選，也可加自訂 Hashtags。重複標籤只輸出一次，勾選狀態會和 FB 文案一起保存在同一個瀏覽器。
- AI 文字功能產生 2–3 句、約 60–100 個中文字的宣傳開頭，不重複活動時間與參加方式；活動時間、獎勵與條件由程式原樣放入文案。按「用 AI 再換 3 種開場」只會換文案，不會清除兩張海報。最多三篇歷史文案可送至伺服器參考語氣；FB 參考圖不傳給 AI。
- 可匯入／匯出 JSON 風格規則，也可加入歷史 FB 文案與參考圖。歷史文字與尚未保存成案例的貼文會自動存在同一個瀏覽器、同一個網站網域的本機儲存區；再次開啟不必重貼。換裝置、使用另一個部署網址或清除瀏覽器資料時不會同步，請匯出 JSON 備份。參考圖與原廠素材重新整理後會清除。
- Gemini 圖片選用 `gemini-nano-banana-2.1`、文字選用 `gemini-3.8-flash`。完整 AI 海報由前端按所選尺寸輸出 PNG；若改動圖片設定，須重新生成才可下載。圖片微調會把兩種尺寸各自的壓縮圖交給 Gemini，套用同一調整指示；兩張皆完成後才更新畫面。模型仍可能連帶改動文字或角色，完整 AI 海報的中文字、活動數字、角色與 Logo 無法保證完全正確，發布前務必人工校對。

本版本僅提供共用使用密碼與同裝置登入記憶，沒有個人帳號、雲端儲存或 FB 自動發文。若將來要讓多位同事保存活動與素材，需要額外加入權限和資料庫。
